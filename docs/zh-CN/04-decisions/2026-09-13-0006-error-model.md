# 0006: 错误模型

[English](../../04-decisions/2026-09-13-0006-error-model.md) | **简体中文**

- 状态：accepted
- 日期：2026-09-13
- 相关：[错误模型](../01-architecture/12-error-model.md)

## 背景

【事实】供应商 API 调用失败时需要保留 URL、状态码、响应头与响应体供诊断；重试策略需要按错误判断是否可重试（HTTP 408、409、429、5xx 与连接类错误）；工具执行失败通常应回传给模型而非终止调用。

【事实】`thiserror` 是 Rust 库错误类型的事实标准；Clippy `result_large_err` 默认在错误类型超过 128 字节时告警，携带响应体等富字段的变体需要装箱或提高 `large-error-threshold`。

## 决策

1. 规范层 `ProviderError` 枚举（透明包装各具体错误结构体），核心层 `Error` 枚举包装 `ProviderError` 并添加核心特有变体；均为 `#[non_exhaustive]`。
2. 工具错误 `ToolError` 独立，非致命，转换为反馈给模型的错误输出。
3. 错误提供 `is_retryable()`、`is_cancelled()`、`status_code()`、`kind()`。
4. 流中错误以可序列化的 `StreamErrorInfo` 投影传递。
5. `Error` 大小控制在 128 字节以内，大字段装箱。

## 依据

- Rust 类型系统替代 Symbol 标记；枚举支持穷尽处理。
- 结构化字段保留诊断所需的信息（URL、状态码、响应体、用量），不必从消息文本中解析。
- 小尺寸错误避免 `Result` 传递成本。

## 备选方案

- 单一 `Box<dyn Error>`：丢失结构化匹配能力。
- 每个模块独立错误类型且不聚合：调用方需处理多种错误类型。

## 影响

- 新增错误情形需在 `Error` 中新增变体并更新 `kind()` 映射。
- 【事实】（PV-013）原型 `verification/pv013-error-size` 中按本 ADR 装箱后的 `Error` 为 56 字节（内联为 360 字节），`static_assertions::const_assert!(size_of::<Error>() <= 128)` 通过；实现中保留该断言。
